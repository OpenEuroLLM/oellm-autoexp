# Optimized TWEO on corrected B1 Megatron

Release `oellm-32b-b1-tweo-20261002` publishes the exact optimized TWEO source used by the conservative-seeded 80k→100k experiment. Megatron commit `5dd5714035962a581827a4978dc3f51086b7f3ff` builds on corrected B1 `799ff4e6e1c3f6762283c97cd76ab4eb68073720`. All seven numerical source files match the validated runtime SHA-256 values in `versions/tweo_source.json`. No test-only gradient instrumentation is added. The prior legacy/patched B1 recipes and tags remain available unchanged.

TWEO adds a quartic auxiliary gradient at each post-MLP residual output, with mean normalization over elements and layers and explicit pipeline loss scaling. It neither clips values nor adds trainable parameters. The fused Triton adjoint preserves the ordered reference expression; CPU, float64, noncontiguous and subnormal-coefficient cases retain the reference fallback. `--tweo-loss-coeff 0` disables TWEO. `--tweo-implementation reference --tweo-diagnostics-interval 1` selects the diagnostic mode within the released source; the fused profile uses interval100. Setting diagnostics interval0 disables telemetry only, not regularization. CP>1, MoE, MTP, CUDA graphs and per-token loss normalization are explicitly outside the validated scope.

## Reproduce the current calibrated profile

The portable variant is `tweo`, configuration `config/experiments/oellm_32b_dense/b1_reborn_tweo.yaml`. It retains corrected defer-on/gradient-overlap-on B1, delayed hybrid FP8, native fused CE, global LR3e-4, z-loss1e-5, B1 decay scopes and retained Adam/RNG/data state. Saves are synchronous, permanent every2000 updates, own rolling every125. Default topology512 nodes/2048 GPUs; walltime is resolved from live Slurm policy.

| TWEO setting | Current calibrated value |
|---|---:|
| Coefficient | 7.817552855400486e-14 |
| Tau | 3 |
| Absolute coefficient-ramp start | 80000 |
| Coefficient ramp | 100 updates |
| Implementation | fused |
| Diagnostic interval | 100 updates |

This coefficient was calibrated on the conservative-v1-seeded B1 80k checkpoint. It is not a universal model/checkpoint default. For another lineage, first measure residual fourth moments, auxiliary/CE gradient ratios and paired precision/loss behavior, then create a separately versioned calibrated profile. The preset rejects checkpoints earlier than80k. Existing TWEO checkpoints resume with the original80k ramp anchor; neither the TWEO ramp nor Adam is reset. The TWEO coefficient ramp is distinct from the optional B1 learning-rate ramp, which is disabled by default here.

```bash
python tools/b1_run.py prepare --variant tweo \
  --run-root "$RUN_ROOT" --checkpoint "$CHECKPOINT_PARENT/iter_0080000" \
  --data-manifest "$DATA_MANIFEST" --data-cache "$DATA_CACHE" \
  --tokenizer "$TOKENIZER" --image "$TRAINING_SIF" \
  --exclude-file "$EXCLUDE_FILE" --account "$SLURM_ACCOUNT" \
  --end-step 100000
# Review the plan; repeat with --execute to materialize the isolated run.
python tools/b1_run.py verify --run-root "$RUN_ROOT"
python tools/b1_run.py launch --run-root "$RUN_ROOT"            # render only
python tools/b1_run.py launch --run-root "$RUN_ROOT" --execute  # explicit GPU admission
```

Use a verified complete native checkpoint with optimizer and RNG state, never a save in progress. Default shard count2048; an explicitly appropriate `--checkpoint-shards` can describe a different native source. The wrapper is byte-identical to the running TWEO wrapper: it injects all six TWEO arguments, rejects duplicate overrides, checks constructed model configurations and the post-load B1/Adam contract, and records save receipts. Config/source/input hashes and initial launch intent preserve the existing preparer safeguards. Default W&B project for this variant is `oellm_32b_dense_loss-increase_debug`; use `--name`/`--wandb-project` explicitly for another identity.

Native autoexp monitoring and failure handling are included as in the other B1 recipes. Automatic restoration of a dead monitor, mirroring, downstream evaluations, precision/bucket reporting, offline W&B uploading and campaign budgets remain separately configured services; this release does not install another operator's watchers. Existing live TWEO services and sources are not changed by publication. Consult the B1 guide for monitor reattachment and STOP semantics.

## Validation and reusable checks

Historical validation of these exact source bytes includes12 CPU algebra/parser checks, GPU2077909 direct/distributed gradient checks, native retained-Adam rolling save/resume, and16/512-node matched benchmarks2089433/2090027 with64/2048 passing rank receipts. The512-node timing was4.429130s/update fused TWEO versus4.427707 control (0.032% overhead) with telemetry disabled during timed phases. Periodic diagnostics, checkpoint I/O and machine state affect campaign throughput. This is implementation validation, not proof that TWEO improves learning or removes FP8 precision losses.

Portable configuration/source/post-load rejection checks run without a GPU:

```bash
PYTHONPATH=. python -m pytest -q --no-cov \
  tests/integration/test_tweo_recipe.py tests/integration/test_b1_recipes.py \
  tests/integration/test_b1_restore_contract.py tests/integration/test_ce_fp32_config.py
python -m unittest discover -s tests -p test_megatron_release.py -v
```

The original numerical check workers are included unchanged under `tools/`. Inside a compatible training environment, the CPU algebra/parser check is `python tools/b1_tweo_algebra_checks.py --source "$PWD/submodules/Megatron-LM" --output "$OUT/algebra.json"`. For a real four-GPU allocation, set `PYTHONPATH="$PWD/submodules/Megatron-LM:$PWD/tools"` and run `python -m torch.distributed.run --standalone --nproc-per-node 4 tools/tweo_optimized_checks.py --output "$OUT/gpu-check"`. This includes direct fused/reference/FP64-adjoint comparisons and a real small TP2/PP1–2/SP Megatron gradient test. GPU checks must not run on a login node. These small checks do not replace production-scale native optimizer/resume and throughput validation after future source changes.
